# Historical records

The project contains cumulative development reports produced while the API was
being constructed and optimized. These files are retained because they record
experiments, rejected approaches, validation snapshots, and intermediate
measurements.

The current project status is defined by:

- `README.md`;
- `RELEASE_NOTES.md`;
- `STATUS.md`;
- `API_COVERAGE.md`;
- `docs/PUBLIC_RELEASE_STATUS.md`;
- `docs/CLAIMS_AND_EVIDENCE.md`.

The current 0.18.0 release records are:

- `docs/ARITHMETIC_FUSED_ROOT_ALLOCATION_CONTRACT_0.18.0.md`;
- `docs/ARITHMETIC_FUSED_ROOT_ALLOCATION_HARDENING_VALIDATION_0.18.0.md`;
- `docs/SEMANTIC_CONTRACT_VALIDATION_0.18.0.md`;
- `docs/ALIASING_CONTRACT_VALIDATION_0.18.0.md`;
- `docs/ABI_COMPATIBILITY_0.18.0.md`;
- `docs/COMPLETION_STATUS_0.18.0.md`;
- `docs/PRODUCTION_CHANGESET_0.18.0.json`.

The 0.17.0 transcendental and special-function records and the 0.16.0
certified-constant records remain historical evidence under `docs/`.

Historical files may contain superseded completion percentages, earlier
performance measurements, or future-work language that has since changed.
They must not be quoted as the current release claim without checking the files
above.

The original root entry points are preserved as:

- `docs/history/README_0.10.0_runtime_complete.md`;
- `docs/history/RELEASE_NOTES_legacy_0.10.0.md`;
- `docs/history/SHA256SUMS_0.10.0_runtime_complete.txt`, the checksum
  manifest for the pre-hardening handoff. It is historical and is not expected
  to validate against the current source tree.
